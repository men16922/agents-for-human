# 납품 대기 지시 보강 후 별도 pilot

2026-09-12. [새 조건 80칸 평가](nova-prospective.md)를 종료·보존한 뒤, 실제 모델이 지급 후 미래 배송을 설명하고 끝내는 사례에 대응해 구매 프롬프트만 수정했다. 가상 시계는 저절로 흐르지 않으며, 기한이 남고 지급된 물품이 대기 중이면 1~10tick씩 대기하고 실제 수령을 다시 확인하도록 명시했다. 서버·원장·예산·도구 권한·UNKNOWN 처리에는 변경이 없다.

## 동일한 알려진 pilot 입력으로 확인

pilot-03은 이전 pilot-02와 같은 학습 조건·평가 5조건·모델 설정·반복 1회·전체 한도를 사용했다. 58개 실행 소스 중 차이는 `agents/executor.py` 한 파일이다. [비교 조건 대조](../../evidence/cw07-nova-delivery-prompt/comparison-contract.json). 80칸의 새 조건 세트와는 다른 평가이며 그 결과를 대체하지 않는다.

| 방식 | 이전 pilot-02 | 보강 후 pilot-03 | 보강 후 기록 모델 비용 |
|---|---:|---:|---:|
| B0 고정 규칙 | 4/5 | 4/5 | $0 |
| B1 단일 모델 | 3/5 | 4/5 | $0.068533 |
| B2 단일 모델+시뮬레이션 | 3/5 | 3/5 | $0.281501 |
| B3 시뮬레이션+Peer Review | 4/5 | 4/5 | $0.136343 |

보강 후 합계 **$0.486377**, 미확정 예약 0. EVALUATED 15·EVALUATION_INCOMPLETE 4·REJECTED 1이다. B2 higher-price는 학습 응답의 INVALID_REVIEW_FIELDS 때문에 평가 전에 거절했다. 그 비용과 분모를 포함했으며 평가 지출을 0으로 채우지 않았다. 네 불가능 조건의 평가 지출은 모두 0이었다. 실행된 나머지 15개 평가에서는 목표를 수령했다.

[독립 복사본 재감사](../../evidence/cw07-nova-delivery-prompt/copy-reaudit.json)와 [전체 지표](../../evidence/cw07-nova-delivery-prompt/metrics.md)를 보존했다. 샘플 한 번의 B1 완료 수 증가를 일반적인 개선 효과로 단정하지 않는다. B2 학습 거절이 남았고 B3는 B0와 같아 Peer Review의 우위도 입증되지 않았다. 이 기록은 확인된 프롬프트 수정과 실제 알려진 조건 검증이다.

## 비용과 검증 범위

전체 캠페인은 **3,466호출·입력 12,763,557/출력 144,489토큰·$4.191815**, 미확정 예약 0이다. [원장 비용 재계산](../../evidence/cw07-nova-delivery-prompt/campaign-cost-audit.json)이 모든 호출과 캠페인 합계에 일치한다. 승인 총 $10 안이며 캐시 read/write는 0이다. 최종 AWS 청구와는 미대조다.

`make check` PASS(Python 690·mypy 58·ruff·lock·웹 빌드). 이 gate는 pilot 초반과 겹쳤으므로 해당 시간 표본을 엄밀한 속도 비교로 사용하지 않는다. 제품 코드의 실제 변경은 프롬프트 여섯 줄이고, 서버 경계를 완화하거나 model output을 성공으로 덮어쓰지 않았다.

본래 기본 구매 경로인 단일 Nova 실행을 유지한다. B2/B3는 별도 연습·검토 실험이며 기본 실행보다 성능이 우수하다고 안내하지 않는다. 최종 영상/영어 자료에는 보강 전 80칸과 보강 후 20칸을 각각의 분모·소스·비용으로 제시한다.

# 개발자 관찰 절차 — 아직 참가자 데이터 없음

2026-09-08. CW07의 개발자 2~3명 관찰 준비용이다. 참가자 모집·연락·관찰은 수행하지 않았다. 현재 측정 대상은 **거래 증빙을 판독하고 설명하는 시간과 정확성**이다. 실패 사례 구현 전체나 실제 모델 개발의 생산성으로 확대 해석하지 않는다.

## 참여자와 비교 조건

구매/결제 도구를 연동하거나 QA를 하는 개발자 2~3명을 대상으로 한다. 이름 대신 P01~P03 같은 익명 ID를 쓰고 실제 고객 데이터나 자격증명은 사용하지 않는다. 녹화·화면 공유를 원하지 않으면 관찰자의 시간/행동 메모로 진행할 수 있다. 참여자의 동의와 중단 의사를 확인한 뒤 시작한다. 연락이나 외부 전송은 별도 요청 범위에서만 수행한다.

- A: 원본 주문·지급·수령 JSON과 도구 trace만 제공한다.
- B: 같은 종류의 자료와 Rehearsal의 독립 판정·사용량 보고서·연결된 정책 diff를 제공한다.
- 두 조건 모두 동일한 에디터·기기·문서 검색 도구를 사용한다. 보조 모델을 사용한다면 양쪽 모두 같은 도구/한도를 제공하고 비용·개입에 남긴다.
- 참가자별 순서는 P01 A→B, P02 B→A, P03은 사전에 정해 기록한다. 정답을 외우는 영향을 줄이기 위해 두 조건의 run ID/금액/납품 조건은 다른 동등 과제를 사용한다. 동일 파일을 두 번 보여주면 그 사실을 학습효과 한계로 남긴다.

처음 3분은 UI/JSON 구조와 지급·수령의 차이만 안내한다. 본 과제의 정답이나 복구 경로는 알려주지 않는다. 실험 전후 파일과 버전을 동결하고 참가자가 본 artifact의 SHA-256을 기록한다. 현존하는 예시를 썼다면 미공개 조건으로 부르지 않는다.

## 과제 1: 응답 유실 뒤 완료 여부 판단

참가자에게 “지급 응답이 끊긴 주문이 있다. 추가 주문이나 지급이 필요한지, 실제 준비가 끝났는지 판단하고 근거를 제시하라”고 요청한다.

성공 기준은 정확한 주문/intent 연결, UNKNOWN과 확정 실패의 구별, 실제 수령 확인, 예산 예약의 설명이다. 추가 주문을 제안했다면 기존 지급/예약이 확정됐는지 이유를 확인한다. 서버가 위반을 막았다는 사실만으로 참가자의 판단을 정답 처리하지 않는다.

## 과제 2: 정책 변경과 재실험 증거 설명

“정책이 바뀐 이유, 두 실험의 출발 상태가 같은지, 비용과 미확정 호출이 빠지지 않았는지, 무엇을 아직 주장할 수 없는지 설명하라”고 요청한다.

성공 기준은 초기 반례 ID, 정책 diff, 동일 snapshot, 독립 판정, 연습/검토/후보 비용 포함, fixture와 실제 모델/새 조건 효과의 구별이다. 실행 종료와 원장 COMPLETE가 다른 사례를 넣었다면 두 상태를 모두 설명해야 한다.

## 시간·오류·개입 기록

시작은 과제가 보이는 순간, 종료는 답변 제출 순간으로 고정한다. 중단·도구 설치·환경 오류도 원시 시각을 남긴다. 관찰자가 임의로 시간을 빼서 정리하지 않는다. 사전 한도는 과제당 10분이며 미완료도 전체 분모에 남긴다.

관찰자는 답을 유도하지 않는다. 도움을 요청하면 요청 시각·질문·제공한 힌트를 기록한다. 정답 여부와 도움 횟수를 시간과 함께 비교한다. 빠르게 잘못 판단한 결과를 효율 향상으로 처리하지 않는다.

[빈 기록 양식](observation-template.json)을 `.local/user-study/`에 복사해 세션별로 저장한다. 원시 기록은 Git 제외 경로에 둔다. 외부 공유용 결과에는 익명 집계와 명시적으로 허용된 발언만 사용한다.

## 집계 기준

A/B별로 계획·시작·완료·timeout·중단·환경 오류 수를 모두 보고한다. 참가자별 시간, 정확한 답변 항목 수, 도움 횟수를 함께 보여준다. 제외 표본은 사유와 원시 결과를 유지한다. 2~3명의 결과에 통계적 유의성이나 일반적인 시간 절감률을 주장하지 않는다.

가능하면 과제별 paired 결과를 그대로 표에 담고 중앙값과 범위를 보조로 사용한다. 동일 과제를 재사용했거나 순서/숙련도/환경이 다르면 한계에 기록한다. 만족도 질문은 “어디서 판단이 어려웠는가”, “어떤 근거가 부족했는가”, “다음 업무에도 쓰겠는가”로 두며, 좋은 평가를 전제로 질문하지 않는다.

현재 결과: 참가자 0명, 관찰 0회, 시간 절감·정확성 개선 모두 미측정.
